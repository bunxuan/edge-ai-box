## 智能盒子项目——全量类图与调用关系

---

### 一、类清单总览

整个智能盒子系统共设计约 40 个类（含 5 个层间交互类、4 个数据传输结构体），按三层架构归属如下。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  表示层 (Presentation Layer) — 12 个类                                       │
│                                                                              │
│  协议族（继承 ProtocolBase 抽象基类）：                                         │
│    ProtocolBase                  (协议统一事件接口，抽象基类)                    │
│      ├── MQTTClientAdapter       (MQTT 客户端，连接物联网云平台)                │
│      ├── MQTTServerAdapter       (MQTT 服务端，接收 ESP32/PLC 传感器数据)       │
│      ├── HTTPServerAdapter       (HTTP 服务端，本地 RESTful API)               │
│      └── HTTPClientAdapter       (HTTP 客户端，文件传输/数据上报)                │
│                                                                              │
│  摄像头族：                                                                    │
│    CameraConnectionManager       (摄像头统一管理器)                             │
│      └── CameraInstance          (单路摄像头实例)                               │
│           ├── OnvifSnapshotFetcher  (ONVIF 快照拉取)                           │
│           └── RtspStreamDecoder     (RTSP 流 + 硬件解码)                       │
│                                                                              │

│    ProtocolConfigManager         (JSON 配置读取 + 工厂创建协议/摄像头)           │

│  业务层 (Business Layer) — 16 个类                                            │

│                                                                              │
│  辅助业务模块：                                                                 │
│    TimedCaptureScheduler         (定时抓图调度)                                 │
│    RemoteModelUpdater            (远程模型下载/校验/热切换)                      │
│    LogManager                    (分级日志 + 增量上传)                          │
│    CloudTaskScheduler            (云端任务统一调度)                              │
│    WatchdogMonitor               (看门狗监控线程)                               │
├──────────────────────────────────────────────────────────────────────────────┤
│  数据访问层 (Data Access Layer) — 12 个类                                      │
│                                                                              │
│  设备管理：                                                                    │
│    DevicePollingThread           (时间轮轮询 + 命令执行 + 中断处理)               │
│    DeviceConfigManager           (JSON 设备配置表 + 热加载)                      │
│    DeviceDriver                  (设备驱动抽象基类)                              │
│      ├── GPIODriver              (GPIO 输入/输出 + 中断)                       │
│      ├── ModbusRTUDriver         (RS485 Modbus RTU 协议)                      │
│      ├── I2CDriver               (I2C 总线通信)                                │

│                                                                              │
│  硬件抽象层 HAL：                                                               │
│    HardwareAbstractionLayer      (HAL 门面类，统一入口)                          │

│    CommandQueue                  (命令队列，业务层 → 数据访问层)                  │
│    DeviceStatusCache             (设备状态缓存，数据访问层 → 业务层/表示层)        │
├──────────────────────────────────────────────────────────────────────────────┤

│                                                                              │
│    VideoFrame                    (视频帧对象：camera_id/时间戳/像素数据)          │
│    LayerMessage                  (层间消息：type/camera_id/device_id/payload)   │
│    DeviceCommand                 (设备控制命令：device_id/cmd_type/params)       │
│    DeviceStatus                  (设备状态：device_id/type/online/value)        │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 二、表示层类图

#### 2.1 ProtocolIOThread —— 表示层核心调度器

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  ProtocolIOThread                                                           │
│  ──────────────────                                                         │
│  职责：epoll 事件循环线程，统一调度所有协议 I/O 和摄像头帧采集                   │
│  线程：独立线程（ProtocolIOThread）                                            │
│                                                                             │
│  构造参数：                                                                   │
│    FrameDispatcher        *frame_dispatcher      ← 帧数据出口→业务层          │
│    UpstreamMessageQueue   *upstream_queue         ← 上行消息出口→业务层        │
│    DownstreamMessageQueue *downstream_queue        ← 下行消息入口←业务层       │
│    DeviceStatusCache      *device_cache           ← 设备状态（只读）           │
│                                                                             │
│  核心字段：                                                                   │
│    int                    epoll_fd_                                          │
│    struct epoll_event     events_[64]                                        │
│    int                    timeout_ms_ = 50                                   │
│    unordered_map<int, ProtocolBase*>    fd_to_protocol_                      │
│    unordered_map<int, CameraInstance*>    fd_to_camera_                      │
│    atomic<uint64_t>       heartbeat_                                         │
│                                                                             │
│  公开方法：                                                                   │
│    start() / stop()                      线程生命周期                          │
│    register_protocol(ProtocolBase*)      注册协议 fd 到 epoll                  │
│    unregister_protocol(ProtocolBase*)    注销协议 fd                           │
│    register_camera_fd(int, CameraInstance*)  注册摄像头 fd                     │
│    unregister_camera_fd(int)                 注销摄像头 fd                     │
│                                                                             │
│  私有方法：                                                                   │
│    event_loop()                        epoll 主循环                           │
│    dispatch_readable(int fd)           分发可读事件                            │
│    dispatch_writable(int fd)           分发可写事件                            │
│    process_downstream_messages()       处理下行消息                            │
│    process_camera_timers()             处理摄像头定时拉帧                       │
└─────────────────────────────────────────────────────────────────────────────┘

  ProtocolIOThread 在 event_loop 中调用：
    → ProtocolBase::on_readable(fd)         网络数据到达
    → ProtocolBase::on_writable(fd)         socket 可写
    → ProtocolBase::accept_message(msg)     询问协议是否接受该下行消息
    → ProtocolBase::send_pending()          执行发送
    → CameraInstance::on_data_ready(fd)     摄像头数据到达
    → CameraConnectionManager::check_frame_timers()  定时拉帧检查
```

### 七、典型场景调用链

#### 7.1 场景一：AI 检测到烟火 → WebSocket 推送云端

```
①  CameraInstance::on_data_ready(fd)
      OnvifSnapshotFetcher::on_readable() → 提取 JPEG
      → CameraInstance::on_frame_received(data, len, w, h, fmt)
      → 封装 VideoFrame
      → FrameDispatcher::push(frame)                     ═══ 表示层→业务层

②  FrameScheduler::schedule_next_frame()
      → FrameDispatcher::pop(timeout_ms)                  ═══ 取出帧
      → VideoPreprocessor::preprocess(frame)
        → HAL::RGADriver::resize_and_convert()            硬件加速缩放+色彩转换
      → 预处理帧送入推理队列

③  AIInferenceEngine::infer(preprocessed_frame)
      → InferenceStrategy::select_model(camera_id, "fire_smoke")
      → HAL::NPUDriver::run(input, output)                NPU 执行推理
      → 解析检测结果：发现烟火，置信度 0.95
      → ResultBuffer::set(camera_id, result)              缓存结果
      → AnomalyImageBuffer::push(frame, SEVERITY_CRITICAL) 缓存异常图片
      → DownstreamMessageQueue::push(MSG_REPORT_DETECTION) ═══ 业务层→表示层

④  ProtocolIOThread::process_downstream_messages()
      → DownstreamMessageQueue::pop_batch_priority()       ═══ 取出消息
      → MQTTClientAdapter::accept_message(MSG_REPORT_DETECTION) → true
      → MQTTClientAdapter::publish_detection(camera_id, result)
        → MQTT PUBLISH 到主题 /device/{id}/report/detection
      → 数据发送到物联网云平台

⑤  同时，CloudTaskScheduler 调度异常图片上传：
      → AnomalyImageBuffer::pop_for_upload()              取出异常图片
      → HTTPClientAdapter::submit_upload(url, file_path)  提交上传任务
      → 状态机驱动：DNS→TCP→TLS→HTTP POST 分片发送
```

#### 7.2 场景二：云端下发模型更新 → 热切换

```
①  ProtocolIOThread::event_loop()
      → MQTTClientAdapter::on_readable(fd)
        → mqtt_sync() 收到 PUBLISH 报文
        → handle_mqtt_message(topic="/device/001/cmd/model_update", payload)
        → 解析：url="https://cdn.example.com/models/v2.rknn", version="2.0",
                sha256="abc123..."
        → 封装 LayerMessage{type=MSG_CLOUD_CMD_MODEL_UPDATE}
        → UpstreamMessageQueue::push(msg)                  ═══ 表示层→业务层

②  MessageProcessor::message_loop()
      → UpstreamMessageQueue::pop_batch()                   ═══ 取出消息
      → route_table_[MSG_CLOUD_CMD_MODEL_UPDATE]
      → handle_cloud_cmd_model_update(msg)
        → RemoteModelUpdater::start_update(url, version, sha256)

③  RemoteModelUpdater::start_update()
      → CloudTaskScheduler::submit_task({type=DOWNLOAD, url, save_path})
      → LogManager::log(INFO, "Model update started: v2.0")

④  CloudTaskScheduler → HTTPClientAdapter::submit_download()
      → 状态机驱动：DNS→TCP→TLS→HTTP GET（支持断点续传）
      → 模型文件保存到本地 /models/v2.rknn

⑤  下载完成回调 → RemoteModelUpdater::verify_and_swap()
      → calculate_sha256("/models/v2.rknn") == "abc123..."   校验完整性
      → AIInferenceEngine::hot_swap_model("/models/v2.rknn")
        → NPUDriver::load_model("/models/v2.rknn")          加载新模型
        → 加载成功 → 旧模型保留为回退版本
        → 加载失败 → 自动回退到旧模型
      → DownstreamMessageQueue::push(MSG_REPORT_MODEL_STATUS, success)
        ═══ 业务层→表示层
      → LogManager::log(INFO, "Model updated to v2.0")

⑥  ProtocolIOThread → MQTTClientAdapter::publish()
      → 上报模型更新状态到云端
```

#### 7.3 场景三：设备轮询 → 离线检测 → 告警上报

```
①  DevicePollingThread::polling_loop()
      → execute_polling_round()
        → 时间轮扫描，找到到期设备 device_id=2（温湿度传感器，RS485）
        → try_lock_bus(RS485_1, device_id=2) → 成功
        → ModbusRTUDriver::read_nonblock(2, &status)
          → modbus_read_registers(slave=1, reg=0x0000, count=2)

②  读取超时（设备无响应）：
      → handle_poll_timeout(2)
        → timeout_count++（当前 = 3，达到 OFFLINE_THRESHOLD）
        → device_cache_->mark_offline(2)                     ═══ 更新状态缓存
        → 封装 LayerMessage{type=MSG_DEVICE_EVENT,
                            payload=DeviceEventPayload{
                              event_type=DEVICE_OFFLINE,
                              device_id=2,
                              consecutive_timeouts=3}}
        → UpstreamMessageQueue::push(msg)                    ═══ 数据访问层→业务层

③  MessageProcessor::message_loop()
      → pop_batch() 取出 MSG_DEVICE_EVENT
      → handle_device_event(msg)
        → device_cache_->get(2, &status) 确认离线
        → DownstreamMessageQueue::push(MSG_REPORT_STATUS,
            {device_id=2, event="offline"})                  ═══ 业务层→表示层
        → LogManager::log(WARN, "Device 2 offline")

④  ProtocolIOThread → MQTTClientAdapter::publish_device_event()
      → 上报设备离线事件到云端

⑤  设备恢复后（下次轮询成功）：
      → handle_poll_success(2, status)
        → timeout_count = 0
        → device_cache_->update(2, status)                  恢复在线
        → UpstreamMessageQueue::push(DEVICE_RECOVERED)       上报恢复事件
```

#### 7.4 场景四：本地 HTTP 控制 → 执行器操作

```
①  HTTPServerAdapter::on_readable(fd)
      → on_request_ready(client_fd)
        → 解析 HTTP 请求：POST /api/devices/10/control
          Body: {"cmd": "open_door"}
        → verify_token(auth_header) → 通过
        → 封装 LayerMessage{type=MSG_LOCAL_CONTROL,
                            device_id=10,
                            payload={cmd:"open_door"}}
        → UpstreamMessageQueue::push(msg)                    ═══ 表示层→业务层
        → pending_requests_[request_id] = {client_fd, ...}   记录待响应

②  MessageProcessor::handle_local_control(msg)
      → execute_device_command(10, CMD_OPEN_DOOR, params, 5000, &result)
        → cmd_queue_->submit(&cmd)                           ═══ 业务层→数据访问层
          内部阻塞等待（信号量，最多 5000ms）

③  DevicePollingThread::execute_command_if_available()
      → cmd_queue_->try_pop()                                ═══ 取出命令
      → 找到 device_id=10 的 PollingEntry
      → try_lock_bus(GPIO, 10) → 成功
      → GPIODriver::write_command(10, CMD_OPEN_DOOR, ...)
        → gpio_write_value(fd, active_level)                 继电器吸合
        → schedule_restore_timer(10, 2000)                   2秒后自动恢复
      → cmd_queue_->complete(cmd, {success=true})            回写结果
        → sem_signal(cmd.done_sem)                           唤醒业务层

④  MessageProcessor（被信号量唤醒）
      → 收到 result = {success=true}
      → send_response(msg, MSG_REPORT_CMD_RESULT, {success=true})
      → DownstreamMessageQueue::push(response)               ═══ 业务层→表示层

⑤  ProtocolIOThread::process_downstream_messages()
      → HTTPServerAdapter::accept_message(MSG_REPORT_CMD_RESULT) → true
      → HTTPServerAdapter::enqueue_response(client_fd, 200,
            "application/json", {"success":true})
      → HTTP 响应发送回浏览器
```
