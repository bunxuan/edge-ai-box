## 智能盒子业务层设计实现文档

---

### 一、业务层整体结构

业务层是智能盒子的核心处理引擎，采用异步事件驱动机制，负责从表示层接收视频帧和外部消息，完成 AI 推理、帧调度、定时抓图、远程模型更新、运行日志管理、云端任务协调等全部核心业务，并向数据访问层下发设备控制命令。整个业务层由 3 个工作线程（RK3588 平台可扩展至 4~5 个）驱动，内部共 16 个类协同工作。

三个线程的职责边界：MessageProcessor 是业务层的"入口"，所有来自表示层和数据访问层的消息都经过它路由分发；AIInferenceEngine 是业务层的"算力核心"，独占一个线程以保证推理的实时性和连续性；WatchdogMonitor 是业务层的"保险丝"，独立于其他两个线程，监控它们的健康状态。三个线程之间通过消息队列和共享缓存协作，不存在跨线程的直接同步函数调用。

### 二、MessageProcessor 消息处理线程

MessageProcessor 是业务层的路由中枢，也是整个系统消息流的汇聚点。它从 UpstreamMessageQueue 批量取出消息，按类型路由到对应的处理逻辑，并将结果写入 DownstreamMessageQueue 或 CommandQueue。

#### 2.1 类定义

```cpp
class MessageProcessor {
public:
    MessageProcessor(
        // ── 层间通道 ──
        UpstreamMessageQueue   *upstream_queue,       // 消息入口
        DownstreamMessageQueue *downstream_queue,     // 消息出口
        CommandQueue           *cmd_queue,            // 控制命令出口
        FrameDispatcher        *frame_dispatcher,     // 帧分发器（供抓图模块使用）
        DeviceStatusCache      *device_cache,         // 设备状态缓存
        // ── 业务层内部模块 ──
        FrameScheduler         *frame_scheduler,
        ResultBuffer           *result_buffer,
        TimedCaptureScheduler  *capture_scheduler,
        RemoteModelUpdater     *model_updater,
        LogManager             *log_manager,
        CloudTaskScheduler     *cloud_scheduler
    );

    void start();     // 启动消息处理线程
    void stop();      // 停止（优雅退出）

private:
    void message_loop();    // 消息处理主循环

    // ── 消息路由表（函数指针数组，以 MsgType 为索引）──
    typedef void (MessageProcessor::*MsgHandler)(const LayerMessage&);
    void init_route_table();
    MsgHandler route_table_[MSG_TYPE_COUNT];

    // ── 各类消息的处理函数 ──
    void handle_sensor_data(const LayerMessage &msg);
    void handle_cloud_cmd_model_update(const LayerMessage &msg);
    void handle_cloud_cmd_capture_freq(const LayerMessage &msg);
    void handle_cloud_cmd_log_level(const LayerMessage &msg);
    void handle_cloud_cmd_instant_capture(const LayerMessage &msg);
    void handle_cloud_cmd_camera_config(const LayerMessage &msg);
    void handle_local_control(const LayerMessage &msg);
    void handle_device_event(const LayerMessage &msg);
    void handle_status_query(const LayerMessage &msg);

    // ── 辅助方法 ──
    void send_response(const LayerMessage &request, MsgType resp_type,
                       const void *payload, size_t payload_len);
    bool execute_device_command(int device_id, CmdType cmd,
                                void *params, uint32_t timeout_ms,
                                CmdResult *out_result);

    // ── 层间通道指针 ──
    UpstreamMessageQueue   *upstream_queue_;
    DownstreamMessageQueue *downstream_queue_;
    CommandQueue           *cmd_queue_;
    FrameDispatcher        *frame_dispatcher_;
    DeviceStatusCache      *device_cache_;

    // ── 业务模块指针 ──
    FrameScheduler         *frame_scheduler_;
    ResultBuffer           *result_buffer_;
    TimedCaptureScheduler  *capture_scheduler_;
    RemoteModelUpdater     *model_updater_;
    LogManager             *log_manager_;
    CloudTaskScheduler     *cloud_scheduler_;

    // ── 心跳 ──
    std::atomic<uint64_t>   heartbeat_;

    // ── 统计 ──
    uint64_t msg_processed_count_;      // 已处理消息总数
    uint64_t msg_error_count_;          // 处理失败的消息数
};
```

#### 2.2 消息主循环

message_loop 是 MessageProcessor 的核心执行逻辑，采用"批量取出 → 逐条路由"的模式。批量取出减少了锁竞争——每次加锁取出一批消息（最多 32 条），然后在无锁状态下逐条处理。

```cpp
void MessageProcessor::message_loop() {
    LayerMessage batch[32];     // 批量取出缓冲区

    while (!stop_flag_.load(std::memory_order_relaxed)) {

        // ① 批量取出消息（阻塞等待，最多等 100ms）
        int count = upstream_queue_->pop_batch(batch, 32, 100);
        if (count == 0) {
            // 超时但无消息，更新心跳后继续
            heartbeat_.store(get_monotonic_ms());
            continue;
        }

        // ② 逐条路由处理
        for (int i = 0; i < count; i++) {
            MsgType type = batch[i].type;

            if (type >= 0 && type < MSG_TYPE_COUNT && route_table_[type]) {
                // 通过路由表调用对应处理函数
                (this->*(route_table_[type]))(batch[i]);
                msg_processed_count_++;
            } else {
                LOG_WARN("MessageProcessor: unknown msg type %d", type);
                msg_error_count_++;
            }

            // 释放 payload 内存（pop_batch 时已拷贝）
            free_payload(batch[i]);
        }

        // ③ 更新心跳
        heartbeat_.store(get_monotonic_ms());
    }
}
```

#### 2.3 消息路由表

路由表用函数指针数组实现，以 MsgType 枚举值为索引，O(1) 时间复杂度完成路由，比 if-else/switch 链更高效且易于扩展。新增消息类型只需在 init_route_table 中注册一条映射。

```cpp
void MessageProcessor::init_route_table() {
    // 初始化所有槽位为 NULL
    memset(route_table_, 0, sizeof(route_table_));

    // ── 传感器数据 ──
    route_table_[MSG_SENSOR_DATA]           = &MessageProcessor::handle_sensor_data;

    // ── 云端管理指令 ──
    route_table_[MSG_CLOUD_CMD_MODEL_UPDATE] = &MessageProcessor::handle_cloud_cmd_model_update;
    route_table_[MSG_CLOUD_CMD_CAPTURE_FREQ] = &MessageProcessor::handle_cloud_cmd_capture_freq;
    route_table_[MSG_CLOUD_CMD_LOG_LEVEL]    = &MessageProcessor::handle_cloud_cmd_log_level;
    route_table_[MSG_CLOUD_CMD_INSTANT_CAPTURE] = &MessageProcessor::handle_cloud_cmd_instant_capture;
    route_table_[MSG_CLOUD_CMD_CAMERA_CONFIG]= &MessageProcessor::handle_cloud_cmd_camera_config;

    // ── 本地控制 ──
    route_table_[MSG_LOCAL_CONTROL]          = &MessageProcessor::handle_local_control;

    // ── 设备事件 ──
    route_table_[MSG_DEVICE_EVENT]           = &MessageProcessor::handle_device_event;

    // ── 状态查询 ──
    route_table_[MSG_STATUS_QUERY]           = &MessageProcessor::handle_status_query;
}
```

#### 2.4 关键消息处理函数实现

**handle_status_query — 状态查询（最快路径）**

状态查询是延迟敏感的操作，必须直接从缓存返回最新值，不等待新推理或新轮询。

```cpp
void MessageProcessor::handle_status_query(const LayerMessage &msg) {
    LayerMessage response;
    response.type = MSG_REPORT_STATUS;
    response.camera_id = msg.camera_id;
    response.device_id = msg.device_id;
    response.timestamp = get_monotonic_us();

    if (msg.device_id >= 0) {
        // 查询设备状态：直接从 DeviceStatusCache 读取
        DeviceStatus status;
        if (device_cache_->get(msg.device_id, &status)) {
            response.payload = malloc(sizeof(DeviceStatus));
            memcpy(response.payload, &status, sizeof(DeviceStatus));
            response.payload_len = sizeof(DeviceStatus);
        } else {
            // 设备不存在
            response.type = MSG_REPORT_ERROR;
        }
    }

    if (msg.camera_id >= 0) {
        // 查询摄像头最新 AI 检测结果：直接从 ResultBuffer 读取
        DetectionResult result;
        if (result_buffer_->get(msg.camera_id, &result)) {
            response.payload = malloc(sizeof(DetectionResult));
            memcpy(response.payload, &result, sizeof(DetectionResult));
            response.payload_len = sizeof(DetectionResult);
        }
    }

    // 写入下行消息队列，由表示层返回给请求方
    downstream_queue_->push(response);
}
```

**handle_local_control — 本地控制命令**

本地控制需要下发到数据访问层执行，采用"请求-响应"同步模式。MessageProcessor 通过 CommandQueue 下发命令后阻塞等待结果，设置超时防止死等。

```cpp
void MessageProcessor::handle_local_control(const LayerMessage &msg) {
    // 解析控制命令
    ControlRequest *req = (ControlRequest*)msg.payload;

    // 权限校验（检查 Token 或操作权限）
    if (!verify_permission(req)) {
        send_response(msg, MSG_REPORT_CMD_RESULT,
                      &(CmdResult){.success = false, .error = "PERMISSION_DENIED"},
                      sizeof(CmdResult));
        return;
    }

    // 构造设备命令
    CmdResult result = {};
    sem_t done_sem;
    sem_init(&done_sem, 0, 0);

    DeviceCommand cmd;
    cmd.device_id  = req->device_id;
    cmd.cmd_type   = req->cmd_type;
    cmd.params     = req->params;
    cmd.timeout_ms = req->timeout_ms > 0 ? req->timeout_ms : 5000;
    cmd.result     = &result;
    cmd.done_sem   = &done_sem;

    // 下发到数据访问层并等待结果
    bool ok = execute_device_command(cmd.device_id, cmd.cmd_type,
                                     cmd.params, cmd.timeout_ms, &result);

    // 将执行结果写入下行消息队列
    send_response(msg, MSG_REPORT_CMD_RESULT, &result, sizeof(CmdResult));

    // 记录操作日志
    log_manager_->log(LOG_LEVEL_INFO, "MessageProcessor",
                      "Control cmd=%d device=%d result=%s",
                      cmd.cmd_type, cmd.device_id,
                      result.success ? "OK" : "FAIL");
}

bool MessageProcessor::execute_device_command(
        int device_id, CmdType cmd_type,
        void *params, uint32_t timeout_ms,
        CmdResult *out_result) {

    sem_t done_sem;
    sem_init(&done_sem, 0, 0);

    DeviceCommand cmd = {
        .device_id  = device_id,
        .cmd_type   = cmd_type,
        .params     = params,
        .timeout_ms = timeout_ms,
        .result     = out_result,
        .done_sem   = &done_sem
    };

    // 写入命令队列
    cmd_queue_->submit(&cmd);

    // 阻塞等待数据访问层执行完毕（带超时）
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    ts.tv_sec  += timeout_ms / 1000;
    ts.tv_nsec += (timeout_ms % 1000) * 1000000;
    if (ts.tv_nsec >= 1000000000) { ts.tv_sec++; ts.tv_nsec -= 1000000000; }

    int ret = sem_timedwait(&done_sem, &ts);
    sem_destroy(&done_sem);

    if (ret != 0) {
        // 超时
        out_result->success = false;
        out_result->error = "TIMEOUT";
        LOG_WARN("Device command timeout: device=%d cmd=%d", device_id, cmd_type);
        return false;
    }
    return out_result->success;
}
```

```cpp
void MessageProcessor::handle_cloud_cmd_camera_config(const LayerMessage &msg) {
    CameraConfigChange *change = (CameraConfigChange*)msg.payload;

    switch (change->action) {
        case CAMERA_ADD:
            // 通知表示层的 CameraConnectionManager 新增摄像头

            LOG_INFO("MessageProcessor", "Removing camera %d", change->camera_id);
            send_response(msg, MSG_CLOUD_CMD_CAMERA_CONFIG,

        case CAMERA_UPDATE:

                     change->camera_id);
            send_response(msg, MSG_CLOUD_CMD_CAMERA_CONFIG,
                          change, sizeof(CameraConfigChange));
```

### 三、FrameScheduler 帧调度器

FrameScheduler 是 AI 推理管线的前端，负责从 FrameDispatcher 中按优先级和抽帧间隔取出帧数据，送入预处理队列。它是决定"哪些帧在什么时候被处理"的关键组件。

#### 3.1 类定义

```cpp
class FrameScheduler {
public:
    FrameScheduler(FrameDispatcher *frame_dispatcher,
                   int max_camera_count);
    ~FrameScheduler();

    // 启动调度（在 AI 推理线程中调用，非独立线程）
    // 返回下一帧待处理帧，阻塞等待直到有帧就绪或超时
    VideoFrame* schedule_next(int timeout_ms);

    // ── 配置管理 ──
    void set_camera_config(int camera_id, int priority,
                           int interval_sec, bool enable_ai);
    void remove_camera(int camera_id);

    // ── 负载自适应 ──
    void report_preprocess_queue_depth(int depth);

    // ── 统计 ──
    struct Stats {
        uint64_t total_frames_scheduled;
        uint64_t total_frames_skipped;     // 因降频跳过的帧数
        double   avg_schedule_latency_us;  // 平均调度延迟
    };
    Stats get_stats() const;

private:
    // ── 每路摄像头的调度状态 ──
    struct CameraScheduleEntry {
        int      camera_id;
        int      priority;               // 1=最高, 5=最低
        int      interval_ms;            // 抽帧间隔（毫秒）
        bool     enable_ai;              // 是否启用 AI
        uint64_t next_process_time;      // 下次应处理时间
        uint64_t last_process_time;      // 上次处理时间
        int      effective_interval_ms;  // 实际生效间隔（可能被降频拉大）
        uint64_t frames_processed;       // 已处理帧数
        uint64_t frames_skipped;         // 被跳过的帧数
    };

    // 按优先级选取下一路摄像头
    int select_next_camera();

    // 自适应降频逻辑
    void adapt_frequency();

    FrameDispatcher *frame_dispatcher_;

    // 摄像头调度表（按 camera_id 索引）
    std::unordered_map<int, CameraScheduleEntry> schedule_table_;
    pthread_mutex_t table_mutex_;

    // 负载反馈
    int preprocess_queue_depth_;         // 预处理队列当前深度
    int overload_threshold_;             // 过载阈值（默认 8 帧）
    int frequency_scale_factor_;         // 降频倍率（2=间隔翻倍）
};
```

#### 3.2 优先级调度算法

schedule_next 的核心是 select_next_camera 方法，它从所有就绪的摄像头中选取优先级最高的一路。"就绪"的定义是：当前时间 >= 该摄像头的 next_process_time。

```cpp
VideoFrame* FrameScheduler::schedule_next(int timeout_ms) {
    uint64_t deadline = get_monotonic_ms() + timeout_ms;

    while (get_monotonic_ms() < deadline) {
        pthread_mutex_lock(&table_mutex_);

        int cam_id = select_next_camera();

        if (cam_id >= 0) {
            // 找到就绪的摄像头，从 FrameDispatcher 取帧
            VideoFrame *frame = frame_dispatcher_->pop(0);  // 非阻塞取
            if (frame && frame->camera_id == cam_id) {
                // 更新调度状态
                auto &entry = schedule_table_[cam_id];
                entry.last_process_time = get_monotonic_ms();
                entry.next_process_time = entry.last_process_time
                                        + entry.effective_interval_ms;
                entry.frames_processed++;

                pthread_mutex_unlock(&table_mutex_);
                return frame;
            }
            // 帧不属于目标摄像头（可能被其他路径消费），重试
            if (frame) {
                // 不是目标摄像头的帧，放回或丢弃
                frame_dispatcher_->push_back(frame);
            }
        }

        pthread_mutex_unlock(&table_mutex_);

        // 没有就绪的摄像头，短暂休眠后重试
        usleep(1000);  // 1ms
    }
    return nullptr;  // 超时
}

int FrameScheduler::select_next_camera() {
    // 按优先级分组扫描：先扫优先级 1（最高），再扫 2，依次类推
    // 同优先级内按"最久未处理"排序（保证公平性）

    int best_cam = -1;
    int best_priority = INT_MAX;
    uint64_t oldest_time = UINT64_MAX;
    uint64_t now = get_monotonic_ms();

    for (auto &[id, entry] : schedule_table_) {
        if (!entry.enable_ai) continue;
        if (now < entry.next_process_time) continue;  // 未就绪

        // 优先级更高（数值更小），或同优先级但更久未处理
        if (entry.priority < best_priority ||
            (entry.priority == best_priority &&
             entry.last_process_time < oldest_time)) {
            best_cam = id;
            best_priority = entry.priority;
            oldest_time = entry.last_process_time;
        }
    }

    return best_cam;
}
```

#### 3.3 自适应降频

当 AI 推理负载过高时（预处理队列积压超过阈值），FrameScheduler 自动降低低优先级摄像头的处理频率，保证关键摄像头的检测时效性。

```cpp
void FrameScheduler::report_preprocess_queue_depth(int depth) {
    preprocess_queue_depth_ = depth;
    if (depth > overload_threshold_) {
        adapt_frequency();
    }
}

void FrameScheduler::adapt_frequency() {
    // 降频策略：优先级 >= 3 的摄像头，间隔翻倍
    // 优先级 <= 2 的关键摄像头不受影响
    for (auto &[id, entry] : schedule_table_) {
        if (entry.priority >= 3) {
            entry.effective_interval_ms = entry.interval_ms * frequency_scale_factor_;
            entry.frames_skipped++;
        }
        // 优先级 1~2 的关键摄像头保持原始间隔
    }

    LOG_WARN("FrameScheduler", "Load adaptation: queue_depth=%d, "
             "low-priority cameras interval x%d",
             preprocess_queue_depth_, frequency_scale_factor_);
}
```

降频的恢复是自动的：当预处理队列深度回落到阈值以下时，下一轮调度自然使用原始间隔（effective_interval_ms 在每次 adapt_frequency 调用时重新计算）。

```cpp
bool VideoPreprocessor::preprocess(VideoFrame *input, VideoFrame *output,
                                   int target_width, int target_height,
                                   PixelFormat target_format) {
    // ① 从内存池获取输出帧（预分配，零拷贝）
    VideoFrame *out_frame = acquire_frame_from_pool();
    if (!out_frame) {
        LOG_ERROR("VideoPreprocessor", "Frame pool exhausted");
        return false;
    }

    // ② 配置 RGA 任务参数
    RgaTask task;
    task.src_fd     = input->data;           // 源图像数据
    task.src_w      = input->width;
    task.src_h      = input->height;
    task.src_fmt    = input->format;         // 通常为 NV12

    task.dst_fd     = out_frame->data;       // 目标缓冲区
    task.dst_w      = target_width;          // 如 640
    task.dst_h      = target_height;         // 如 640
    task.dst_fmt    = target_format;         // 如 RGB888

    task.operation  = RGA_OP_RESIZE | RGA_OP_CSC;  // 缩放 + 色彩空间转换

    // ③ 提交 RGA 任务（硬件加速，CPU 不等待像素处理）
    int ret = rga_->blit(&task);
    if (ret != 0) {
        LOG_ERROR("VideoPreprocessor", "RGA blit failed: %d", ret);
        release_frame_to_pool(out_frame);
        return false;
    }

    // ④ 填充输出帧元数据
    out_frame->camera_id    = input->camera_id;
    out_frame->capture_time = input->capture_time;
    out_frame->width        = target_width;
    out_frame->height       = target_height;
    out_frame->format       = target_format;
    out_frame->data_len     = target_width * target_height * 3;  // RGB888
    out_frame->owner        = OWNED;

    *output = *out_frame;
    return true;
}
```

RGA 处理一帧 640×640 的缩放+色彩转换仅需 0.1~0.3ms（对比 CPU 软件处理约 2~3ms），16 路摄像头的预处理总耗时不超过 5ms，完全不是性能瓶颈。

```cpp
void AIInferenceEngine::inference_loop() {
    while (!stop_flag_.load(std::memory_order_relaxed)) {

        // ① 从 FrameScheduler 获取下一帧（阻塞等待，超时 1 秒）
        VideoFrame *frame = frame_scheduler_->schedule_next(1000);
        if (!frame) {
            heartbeat_.store(get_monotonic_ms());
            continue;
        }

        // ② 查找该摄像头的推理策略
        InferenceStrategy *strategy = nullptr;
        pthread_mutex_lock(&strategy_mutex_);
        auto it = strategies_.find(frame->camera_id);
        if (it != strategies_.end()) {
            strategy = it->second;
        }
        pthread_mutex_unlock(&strategy_mutex_);

        if (!strategy) {
            // 该摄像头未配置 AI 检测，丢弃帧
            release_frame(frame);
            continue;
        }

        // ③ 预处理（RGA 硬件加速）
        VideoFrame preprocessed;
        int model_input_w = strategy->get_input_width();   // 如 640
        int model_input_h = strategy->get_input_height();   // 如 640

        if (!preprocessor_->preprocess(frame, &preprocessed,
                                       model_input_w, model_input_h,
                                       PIXEL_FORMAT_RGB888)) {
            LOG_ERROR("AIInference", "Preprocess failed for camera %d",
                      frame->camera_id);
            release_frame(frame);
            continue;
        }

        // ④ 执行 NPU 推理（带超时保护）
        uint64_t infer_start = get_monotonic_ms();
        DetectionResult result = run_inference(&preprocessed, strategy);
        uint64_t infer_elapsed = get_monotonic_ms() - infer_start;

        // ⑤ 更新统计
        update_stats(infer_elapsed);

        // ⑥ 写入结果缓冲（所有摄像头，无论是否检测到异常）
        result.camera_id = frame->camera_id;
        result.timestamp = get_monotonic_us();
        result_buffer_->set(frame->camera_id, result);

        // ⑦ 如果检测到异常事件
        if (result.is_anomaly) {
            on_anomaly_detected(frame, result);
        }

        // ⑧ 上报检测结果到云端（通过 DownstreamMessageQueue）
        LayerMessage report;
        report.type       = MSG_REPORT_DETECTION;
        report.camera_id  = frame->camera_id;
        report.timestamp  = result.timestamp;
        report.payload    = malloc(sizeof(DetectionResult));
        memcpy(report.payload, &result, sizeof(DetectionResult));
        report.payload_len = sizeof(DetectionResult);
        downstream_queue_->push(report);

        // ⑨ 释放帧资源
        release_frame(frame);
        release_frame(&preprocessed);

        // ⑩ 更新心跳
        heartbeat_.store(get_monotonic_ms());
    }
}
```

#### 5.3 单帧推理与超时保护

```cpp
DetectionResult AIInferenceEngine::run_inference(
        VideoFrame *frame, InferenceStrategy *strategy) {

    DetectionResult result = {};
    result.is_anomaly = false;

    // 获取该摄像头对应的模型
    int model_id = strategy->get_model_id();
    auto it = models_.find(model_id);
    if (it == models_.end() || !it->second.loaded) {
        LOG_ERROR("AIInference", "Model %d not loaded", model_id);
        result.error = "MODEL_NOT_LOADED";
        return result;
    }

    ModelSlot &slot = it->second;
    pthread_mutex_lock(&slot.lock);

    // 设置推理超时定时器（使用 timerfd 或 pthread 条件变量超时）
    // 这里用简化方式：在独立线程中监控超时
    bool timed_out = false;
    auto timeout_checker = std::async(std::launch::async, [&]() {
        usleep(inference_timeout_ms_ * 1000);
        // 如果推理还没完成，标记超时
        if (!result.completed) {
            timed_out = true;
            npu_driver_->abort(slot.context);  // 中止 NPU 推理
        }
    });

    // 执行 RKNN 推理
    // rknn_inputs_set → rknn_run → rknn_outputs_get
    int ret = npu_driver_->infer(slot.context,
                                 frame->data, frame->data_len,
                                 frame->width, frame->height,
                                 frame->format);

    if (timed_out) {
        // 推理超时
        on_inference_timeout(frame);
        pthread_mutex_unlock(&slot.lock);
        result.error = "INFERENCE_TIMEOUT";
        return result;
    }

    if (ret != 0) {
        LOG_ERROR("AIInference", "NPU infer failed: %d", ret);
        pthread_mutex_unlock(&slot.lock);
        result.error = "NPU_ERROR";
        return result;
    }

    // 后处理：NMS + 置信度过滤
    result = strategy->post_process(slot.context);
    result.completed = true;

    pthread_mutex_unlock(&slot.lock);
    return result;
}

void AIInferenceEngine::on_inference_timeout(VideoFrame *frame) {
    stats_.timeout_count++;
    LOG_WARN("AIInference", "Inference timeout for camera %d, skipping frame",
             frame->camera_id);
    // 超时后自动跳过当前帧，继续处理下一帧
    // 保证管线不堵塞
}
```

#### 5.4 模型热切换

```cpp
bool AIInferenceEngine::hot_swap_model(int model_id, const char *new_rknn_path) {
    auto it = models_.find(model_id);
    if (it == models_.end()) {
        LOG_ERROR("AIInference", "Model %d not found for hot swap", model_id);
        return false;
    }

    ModelSlot &old_slot = it->second;
    std::string old_path = old_slot.model_path;

    // ① 在后台加载新模型（不影响当前推理）
    ModelSlot new_slot;
    new_slot.model_id = model_id;
    new_slot.model_path = new_rknn_path;
    new_slot.loaded = false;

    int ret = npu_driver_->load_model(new_rknn_path, &new_slot.context);
    if (ret != 0) {
        LOG_ERROR("AIInference", "New model load failed: %d, keeping old model", ret);
        // 加载失败，保留旧模型继续运行
        return false;
    }
    new_slot.loaded = true;

    // ② 原子切换：加锁替换模型上下文
    pthread_mutex_lock(&old_slot.lock);

    // 保存旧上下文（用于失败时回退）
    rknn_context old_ctx = old_slot.context;

    // 切换到新模型
    old_slot.context = new_slot.context;
    old_slot.model_path = new_slot.model_path;

    pthread_mutex_unlock(&old_slot.lock);

    // ③ 释放旧模型内存
    npu_driver_->unload_model(old_ctx);

    LOG_INFO("AIInference", "Model %d hot swapped to %s", model_id, new_rknn_path);
    return true;
}
```

热切换的关键是"双缓冲"思想：新模型在后台加载完成后，通过一次加锁操作将推理上下文从旧模型切换到新模型。切换过程中 AI 推理线程最多阻塞几毫秒（加锁+指针赋值的开销），对实时性影响可忽略。如果新模型加载失败，旧模型完全不受影响，继续正常运行。

```cpp
    };

    // 优先级比较器（严重告警优先）
    struct AnomalyCompare {
        bool operator()(const AnomalyItem &a, const AnomalyItem &b) {
            if (a.severity != b.severity) return a.severity > b.severity;
            return a.timestamp > b.timestamp;  // 同级别按时间排序
        }
    };

    // JPEG 编码
    bool encode_jpeg(VideoFrame *frame, uint8_t **out_data, size_t *out_len);

    // 本地存储管理
    std::string generate_file_path(int camera_id, uint64_t timestamp);
    void enforce_storage_limit();

    // 去重：同一摄像头 N 秒内只保留首张异常图片
    bool is_duplicate(int camera_id, uint64_t timestamp);
    int  dedup_interval_sec_;          // 去重间隔（默认 30 秒）

    std::priority_queue<AnomalyItem,
                        std::vector<AnomalyItem>,
                        AnomalyCompare> queue_;
    pthread_mutex_t queue_mutex_;

    // 去重记录
    std::unordered_map<int, uint64_t> last_anomaly_time_;

    // 本地存储
    std::string storage_dir_;
    size_t      max_storage_bytes_;
    size_t      current_storage_bytes_;
};
```

AnomalyImageBuffer 的三个关键设计：

**优先级队列**：严重告警（烟火、摔倒，severity=1）的图片优先于一般告警（杂物堆放，severity=2~3）。网络带宽有限时，最重要的图片先上传。

**去重逻辑**：同一摄像头在 dedup_interval_sec（默认 30 秒）内只保留第一张异常图片。如果烟火持续存在，30 秒内可能产生数百张异常帧，但只需要上传首张供人工复核。去重大幅减少了存储和网络开销。

**本地暂存与补传**：网络中断时，异常图片不丢弃，而是 JPEG 编码后存入本地文件系统（按摄像头 ID 和日期组织目录）。文件名包含时间戳，便于按时间排序。存储空间有上限（默认 1GB），超限时清理最旧的文件。网络恢复后，recover_local_files 扫描本地目录，按优先级重新排入上传队列。

定时抓图的核心逻辑：

```cpp
void TimedCaptureScheduler::capture_loop() {
    while (!stop_flag_) {
        uint64_t now = get_monotonic_ms();
        pthread_mutex_lock(&entries_mutex_);

        for (auto &[id, entry] : entries_) {
            if (!entry.enabled) continue;
            if (now < entry.next_capture_time) continue;

            // 到达抓拍时刻
            pthread_mutex_unlock(&entries_mutex_);
            do_capture(id);
            pthread_mutex_lock(&entries_mutex_);

            // 更新下次抓拍时间
            entry.next_capture_time = now + entry.interval_sec * 1000;
        }

        pthread_mutex_unlock(&entries_mutex_);
        usleep(500 * 1000);  // 500ms 检查一次
    }
}

void TimedCaptureScheduler::do_capture(int camera_id) {
    // ① 从 FrameDispatcher 获取该摄像头的最新帧
    VideoFrame *frame = frame_dispatcher_->peek_latest(camera_id);
    if (!frame) {
        LOG_WARN("TimedCapture", "No frame available for camera %d", camera_id);
        return;
    }

    // ② JPEG 编码并保存到本地
    std::string local_path;
    if (!encode_and_save(frame, camera_id, &local_path)) {
        LOG_ERROR("TimedCapture", "Save failed for camera %d", camera_id);
        return;
    }

    // ③ 提交上传任务到 CloudTaskScheduler
    cloud_scheduler_->submit_upload(
        /* url */       "/api/captures/upload",
        /* file_path */ local_path,
        /* content_type */ "image/jpeg",
        /* priority */  TASK_PRIORITY_CAPTURE    // 低于异常图片，高于日志
    );

    log_manager_->log(LOG_LEVEL_DEBUG, "TimedCapture",
                      "Camera %d captured and queued for upload", camera_id);
}
```

定时抓图与 AI 推理完全独立——抓图从 FrameDispatcher::peek_latest 取帧（只读，不影响帧的所有权），AI 推理从 FrameScheduler 取帧（所有权转移）。两者互不干扰。

```cpp
void RemoteModelUpdater::update_thread_func(
        const std::string &url, const std::string &version,
        const std::vector<int> &target_cameras) {

    std::string download_path = "/tmp/model_" + version + ".rknn";

    // ① 下载模型文件（通过 CloudTaskScheduler，支持断点续传）
    log_manager_->log(LOG_LEVEL_INFO, "ModelUpdater",
                      "Downloading model %s from %s", version.c_str(), url.c_str());

    int task_id = cloud_scheduler_->submit_download(
        url, download_path, TASK_PRIORITY_DOWNLOAD_MODEL, nullptr);

    // 等待下载完成（CloudTaskScheduler 回调通知）
    bool download_ok = wait_for_task(task_id, 600000);  // 最多等 10 分钟

    if (!download_ok) {
        report_status(version, MODEL_DOWNLOAD_FAILED, "Download failed or timeout");
        return;
    }

    // ② SHA256 校验文件完整性
    if (!verify_model(download_path, expected_hash)) {
        report_status(version, MODEL_VERIFY_FAILED, "SHA256 mismatch");
        remove(download_path.c_str());
        return;
    }

    // ③ 上报"下载完成，准备加载"
    report_status(version, MODEL_DOWNLOADED, "Download complete, loading...");

    // ④ 热切换模型
    for (int cam_id : target_cameras) {
        int model_id = get_model_id_for_camera(cam_id);
        bool ok = inference_engine_->hot_swap_model(model_id, download_path.c_str());

        if (ok) {
            // 更新版本记录（保留上一版本）
            pthread_mutex_lock(&versions_mutex_);
            auto &ver = versions_[model_id];
            ver.previous_path = ver.current_path;
            ver.previous_version = ver.current_version;
            ver.current_path = download_path;
            ver.current_version = version;
            pthread_mutex_unlock(&versions_mutex_);

            report_status(version, MODEL_ACTIVATED, "Model activated");
            log_manager_->log(LOG_LEVEL_INFO, "ModelUpdater",
                              "Model %s activated for camera %d",
                              version.c_str(), cam_id);
        } else {
            report_status(version, MODEL_LOAD_FAILED,
                          "Load failed, rolled back to previous model");
            log_manager_->log(LOG_LEVEL_ERROR, "ModelUpdater",
                              "Model %s load failed for camera %d, rolled back",
                              version.c_str(), cam_id);
        }
    }
}
```

```cpp
void WatchdogMonitor::watchdog_loop() {
    while (!stop_flag_) {
        uint64_t now = get_monotonic_ms();

        pthread_mutex_lock(&mutex_);
        for (auto &wt : watched_) {
            uint64_t last = wt.heartbeat->load(std::memory_order_relaxed);
            uint64_t elapsed = now - last;

            if (elapsed > wt.timeout_ms) {
                // 心跳超时！
                LOG_ERROR("Watchdog", "Thread '%s' heartbeat timeout: %lu ms",
                          wt.name.c_str(), elapsed);

                if (wt.restart_count < wt.max_restarts) {
                    // 尝试重启该模块
                    LOG_WARN("Watchdog", "Restarting module '%s' (attempt %d/%d)",
                             wt.name.c_str(), wt.restart_count + 1, wt.max_restarts);
                    wt.restart_callback();
                    wt.restart_count++;
                    wt.last_seen = now;
                } else {
                    // 超过最大重启次数，触发系统重启
                    LOG_ERROR("Watchdog", "Module '%s' exceeded max restarts, "
                              "triggering system reboot", wt.name.c_str());
                    trigger_system_reboot();
                }
            }
        }
        pthread_mutex_unlock(&mutex_);

        // 喂硬件看门狗
        if (hw_watchdog_fd_ >= 0) {
            write(hw_watchdog_fd_, "1", 1);
        }

        sleep(1);  // 每秒检查一次
    }
}
```

WatchdogMonitor 注册的所有被监控线程：

```
线程名称                心跳指针来源                  超时阈值    重启回调
─────────────────      ──────────────────────────   ────────    ────────────────
"UI"                   UIManager::heartbeat_        3000ms      UIManager::restart()
"ProtocolIO"           ProtocolIOThread::heartbeat_ 3000ms      ProtocolIOThread::restart()
"MessageProcessor"     MessageProcessor::heartbeat_ 3000ms      MessageProcessor::restart()
"AIInference"          AIInferenceEngine::heartbeat_ 5000ms     AIInferenceEngine::restart()
"DevicePolling"        DevicePollingThread::heartbeat_ 3000ms   DevicePollingThread::restart()
```

AI 推理线程的超时阈值设为 5000ms（比其他线程长），因为单帧推理可能耗时 55~65ms，16 路摄像头一轮需要约 1 秒，加上模型加载等偶发操作，需要更宽松的超时容忍度。

#### 13.3 类之间的直接调用关系汇总

```
调用方                       被调用方                     调用场景

MessageProcessor         →   DeviceStatusCache           状态查询时读取设备缓存
MessageProcessor         →   ResultBuffer                状态查询时读取 AI 检测结果
MessageProcessor         →   CommandQueue                控制命令下发到数据访问层
MessageProcessor         →   TimedCaptureScheduler       云端指令：调整抓拍频率/即时抓拍

MessageProcessor         →   LogManager                  云端指令：调整日志级别/即时上传
```

#### 13.4 线程间通信矩阵

```
线程                    读取的队列/缓存                  写入的队列/缓存
─────────────────      ──────────────────────────     ──────────────────────────
MessageProcessor       UpstreamMessageQueue (读)      DownstreamMessageQueue (写)
                       DeviceStatusCache (读)         CommandQueue (写)
                       ResultBuffer (读)

AIInferenceEngine      FrameDispatcher (读: pop)      ResultBuffer (写)
                       VideoPreprocessor (调用)       AnomalyImageBuffer (写)
                                                      DownstreamMessageQueue (写)

WatchdogMonitor        所有线程 heartbeat_ (读)       各模块 restart() (调用)
                       /dev/watchdog (写: 喂狗)
```

所有跨线程的数据传递都通过队列或缓存完成，线程之间不存在直接同步调用。MessageProcessor 和 AIInferenceEngine 之间通过 FrameDispatcher 和 ResultBuffer 间接协作——MessageProcessor 不直接调用 AIInferenceEngine 的任何方法，AIInferenceEngine 也不直接调用 MessageProcessor 的方法。这种松耦合设计使得两个线程可以独立运行、独立重启，互不阻塞。
